# Règles de développement génériques - plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Livrer les règles de dev génériques comme skills `rules-*` du plugin ai-team, préchargés par chaque agent selon son rôle.

**Architecture:** Un skill Markdown par thème dans `skills/rules-<thème>/SKILL.md`, une puce par règle identifiée `AT-...`. Les agents les déclarent dans leur champ `skills:` sous le nom `ai-team:rules-<thème>`. La vérification de nommage demandée par la spec (contraintes) est faite : le 2026-11-28, des sous-agents témoins ont reçu le contenu préchargé avec `rules-probe` comme avec `ai-team:rules-probe` ; la forme `ai-team:` est retenue. Des tests Python stdlib vérifient l'inventaire, les tailles et la matrice agents.

**Tech Stack:** Markdown, Python 3 `unittest`.

**Spec:** `docs/superpowers/specs/2026-11-28-dev-rules-design.md` et son annexe `docs/superpowers/specs/2026-11-28-dev-rules-inventory.md`.

- Skill : frontmatter `name: rules-<thème>` et `description: "Règles de dev ai-team (<thème>), préchargées par les agents. À charger avant d'écrire ou de relire du code <portée>."` (valeur entre guillemets doubles, toujours) ; 110 lignes au plus par fichier ; 950 lignes au plus pour les 15 skills hors packs.
- Rédaction en français ; pas de tiret cadratin, de point médian ni d'emoji ; aucun nom propre à un projet hors packs (`Orbital`, `OrbitalInvest`, `BowTrail`, `Velzon`, `tenant`, `locataire`) ; hors packs, le pack s'écrit toujours `multitenant-postgres`, jamais « multi-tenant » ; une règle qui suppose un outil dit « si l'outil est présent » et ne fait jamais installer.

- Chaque tâche de rédaction commite avec `git add skills/<ses dossiers>` puis `git commit -m "<sujet donné>"`.
- Les valeurs chiffrées des sources sont gardées (400 lignes, 12 caractères, 5 essais / 15 min, `limit` 20 / 100, 30 requêtes, 44 / 24 px, 48 h...).
- Commits : Conventional Commits, sujet en français, aucune mention de Claude ni `Co-Authored-By`, jamais de push.

## Review Focus

- Une règle réécrite perd une valeur ou une condition de sa source : le reviewer compare chaque puce à sa source et à sa ligne d'inventaire.
- Une règle contredit le `CLAUDE.md` global (push sans accord, mention de Claude, compte GitHub) ou `rules/team.md` : signaler en `[bloquant]`.
- Une règle impose un outil non présent sans la condition « si l'outil est présent ».
- Une description de skill trop large qui ferait charger le skill hors de propos par la session principale : elle suit le modèle des contraintes.
- Un agent qui perd un skill qu'il avait avant (le champ `skills:` est complété, jamais remplacé).
